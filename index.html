Guía para ampliar la plataforma

Esta página es un único archivo HTML autocontenido: todo el contenido (módulos, preguntas, casos) vive en objetos de JavaScript cerca del inicio del bloque <script>, y el progreso se guarda en el navegador con localStorage para que el panel y la barra lateral reflejen el avance entre sesiones sin necesidad de un servidor.

1 · Agregar un nuevo procedimiento

Cada procedimiento tiene dos partes: una entrada en el arreglo MODULES (la tarjeta que se ve en Inicio y en Módulos) y un objeto de datos con su contenido clínico, siguiendo el mismo patrón que VITAL_SIGNS (para procedimientos con varios sub-temas) o INJ (para vías/variantes de un mismo procedimiento).

// 1) Tarjeta del módulo
MODULES.push({
  id:'sondaje', ic:'\ud83e\uddfb', title:'Sondaje vesical',
  desc:'Colocación de sonda vesical en paciente adulto.',
  level:'Intermedio', view:'sondaje'
});

// 2) Contenido clínico (mismo patrón que VITAL_SIGNS)
const SONDAJE = {
  objetivo:'...', fundamento:'...',
  materiales:[['\ud83e\uddfa','Sonda Foley'], ['\ud83e\udde4','Guantes est\u00e9riles']],
  prep:['Identificar al paciente', 'Higiene de manos', '...'],
  pasos:[{t:'Paso 1', b:'Descripci\u00f3n...'}],
  errores:['Error frecuente 1', 'Error frecuente 2'],
  caso:{ texto:'...', vitals:[['PA','120/80','mmHg']],
         pregunta:'...', opciones:['A','B','C','D'],
         correcta:1, explicacion:'...' }
};

Después necesitas: (a) agregar sondaje:0 al objeto progress dentro de DEFAULT_STATE para que el nuevo módulo tenga seguimiento propio, (b) crear una vista <section class="view" data-view="sondaje"> en el HTML con la misma estructura que la de Signos vitales, (c) agregar su entrada en el arreglo NAV para que aparezca en el menú lateral, y (d) escribir una función renderSondaje() que pinte el contenido y llamarla una vez dentro de initAll().

2 · Reemplazar íconos por imágenes o ilustraciones propias

Hoy los materiales, tarjetas y anatomía usan emoji (mi-ic, mc-icon) e ilustraciones SVG esquemáticas para que el archivo sea autónomo y liviano. Para usar tus propias imágenes sin depender de una conexión externa (los archivos publicados solo cargan scripts y fuentes de un pequeño listado de proveedores, no imágenes remotas), conviértelas a Base64 e incrústalas directamente:

<div class="mat-item">
  <img src="data:image/png;base64,AAAA..." alt="Sonda Foley" style="width:36px;height:36px;object-fit:contain;">
  <div class="mi-name">Sonda Foley</div>
</div>

Para la anatomía interactiva (venas, sitios de inyección), puedes sustituir el <svg> esquemático por una ilustración de fondo en Base64 dentro de un contenedor, y mantener los <circle class="anat-point"> superpuestos con coordenadas ajustadas a tu imagen, para conservar la interacción de clic y selección.

3 · Conectar con Unity + XR Interaction Toolkit (Meta Quest)

La sección VR ya simula el flujo completo (transición → selección de escenario) de forma local. El punto de integración real es la función pickVRScenario(name): hoy solo muestra una alerta, pero es donde enviarías el escenario y el caso clínico seleccionados como parámetros de sesión hacia el visor.

function pickVRScenario(name){
  const sessionParams = {
    scenario: name,
    caseId: 'canalizacion_iv_01',
    studentProgress: STATE.progress,
    level: overallProgressPct()
  };
  // Opción A: WebSocket a un servidor puente que Unity escucha
  const ws = new WebSocket('wss://tu-servidor-puente/xr-session');
  ws.onopen = () => ws.send(JSON.stringify(sessionParams));

  // Opción B: deep link a una app nativa instalada en el Quest
  // window.location.href = 'vrnursinglab://start?scenario=' + encodeURIComponent(name);
}

Del lado de Unity, el proyecto recibiría estos parámetros con el XR Interaction Toolkit para instanciar el escenario correspondiente (sala de procedimientos, habitación del paciente, urgencias, hospitalización) y cargar el mismo caso clínico que el estudiante vio en la web, de modo que la experiencia inmersiva continúe exactamente donde la dejó en el navegador.
